# Lessons from Superpowers for the `prompt-creator` plugin

**Serves product goal:** "All skills and plugins in this repo MUST follow Claude Code best practices" ([CONVENTIONS.md](../CONVENTIONS.md#claude-code-best-practices-the-baseline-every-skill-follows)) — applied to the one plugin whose *subject matter* is those best practices, and therefore the most damaging place for them to be stale.

> **Basis.** Superpowers **6.3.0**, read from disk at `~/.claude/plugins/cache/claude-plugins-official/superpowers/6.3.0/`; all `path:line` citations are relative to that directory. Upstream is still 6.3.0 (releases page; `commits/main` HEAD `b36e082`, 12 Aug 2026; `plugin.json` on `main` reads `6.3.0`), so nothing post-6.3.0 changes a conclusion here. The live rubric <https://code.claude.com/docs/en/best-practices> was fetched 2026-09-04 and cross-checked against the raw HTML by literal string match. **Implemented** in `prompt-creator` `0.2.0` — all seven proposals (P1–P7) under decisions Q1–Q6; the four rejections stand. This document is now a record, not a proposal: its `path:line` citations describe the files as they were BEFORE that change, so read them as history rather than as current anchors. See [ROADMAP.md](../ROADMAP.md) for what shipped.

## Problem Statement

`prompt-creator` rewrites a rough prompt against the live best-practices page, re-fetched every invocation ([`SKILL.md:21`](../../plugins/prompt-creator/skills/prompt-creator/SKILL.md)). That design is sound and is why it has aged better than a static skill would. Three things have gone wrong underneath it: its offline fallback is dated 2026-07-19 ([`checklist:3`](../../plugins/prompt-creator/skills/prompt-creator/references/best-practices-checklist.md)) and touches most of the live page's 10 body sections only shallowly, with one at zero; its always-loaded body hardcodes a *second, shorter* summary of the same rules (`SKILL.md:25`) that the live fetch does not refresh; and its `description` summarizes its own workflow (`SKILL.md:7-9`), the one authoring pattern Superpowers bans on the basis of a measured behavioral regression.

Superpowers is the most heavily behavior-tested public skill collection available, so it is the right place to look for *mechanisms* — while being an MIT third party whose prose must not be copied ([PITFALLS.md](../PITFALLS.md) records the cost of ignoring that).

## What Superpowers does

**1. A privileged delivery point carrying persuasion, not enforcement.** One hook on one event — `SessionStart` matching `startup|clear|compact` (`hooks/hooks.json:1-17`, the file's only registration) — injects the whole `using-superpowers` body into every session. `SessionStart` is the sole hook event appearing anywhere in 6.3.0: there are **no** `PreToolUse`, `PostToolUse` or `Stop` hooks, so nothing is mechanically blocked. Enforcement is text placed where it cannot be missed: a "if there is even a 1% chance a skill applies, invoke it" mandate with explicit no-choice framing (`skills/using-superpowers/SKILL.md:10-16`) plus a rationalizing-thoughts table (`:33-50`). The injected body is kept small precisely because it is paid for every session — 3108 bytes / 485 words, the smallest of the *discipline* skills (two non-discipline skills are smaller still).

**2. `description` is triggering surface only.** Justified by a recorded failure: a description summarizing a workflow ("code review between tasks") made an agent run **one** review where the body specified **two**; removing the summary restored correct behavior (`skills/writing-skills/SKILL.md:150-158`). A workflow summary becomes a shortcut agents take *instead of* reading the body. 13 of 14 descriptions open with "Use when" and pin a triggering moment.

**3. Guidance form is selected from the observed failure, not by taste.** A four-row table maps baseline failure → correct form (`skills/writing-skills/SKILL.md:463-470`): discipline failures (knows the rule, skips it under pressure) get prohibition + rationalization table; **wrong-shaped output gets a positive recipe instead**. The same section reports that in head-to-head wording tests the prohibition arm produced clearly more of the unwanted content than the recipe arm, and trended worse than the *no-guidance control*. Nuance clauses reopen the negotiation and exemption clauses do not scope (`:472-474`); the bulletproofing toolkit is explicitly limited to discipline failures (`:480`).

**4. Evidence is defined by naming what does *not* count.** `skills/verification-before-completion/SKILL.md` opens with a fenced absolute (`:14-20`), states the rule as a numbered pre-flight run before speaking (`:22-36`), and carries a three-column table whose third column does the work — `Requires` vs **`Not Sufficient`**: tests pass requires command output with zero failures, *not* a previous run; a subagent completed requires a VCS diff, *not* the agent's own success report (`:40-48`). Its reviewer template does **not** pre-narrow severity: all issues, bucketed Critical/Important/Minor, plus strengths and a verdict (`skills/requesting-code-review/code-reviewer.md:143`); the calibration block asks the reviewer to *categorize* accurately, never to suppress (`:78-87`).

**5. Two testing tiers, with a machine-checkable trigger assertion.** `tests/` answers "does the non-LLM plumbing work"; behavioral compliance lives in a separate LLM harness (`docs/testing.md:3-6`). The transferable piece is the trigger suite: `claude -p` with `--output-format stream-json`, grep for a `Skill` tool_use, then locate the first `Skill` invocation and report any earlier non-`Skill`, non-todo `tool_use` as **premature action** (`tests/explicit-skill-requests/run-test.sh:103-118`). Helpers include `assert_order`, proving one concept precedes another in the reply (`tests/claude-code/test-helpers.sh:96-129`).

## Gap analysis

- **G1 — `description` summarizes the workflow.** [`SKILL.md:7-9`](../../plugins/prompt-creator/skills/prompt-creator/SKILL.md) names step 1 (fetch) and step 3 (rewrite), omitting step 2 (diagnose/ask) — the exact regression shape Superpowers measured (`skills/writing-skills/SKILL.md:150-158`). Same clause in [`plugin.json:4`](../../plugins/prompt-creator/.claude-plugin/plugin.json). **This is not currently a repo-rule violation:** [CONVENTIONS.md:20](../CONVENTIONS.md) requires the description to say *when* and bars one that is *only* what-it-does; ours says when, with six trigger forms (five quoted phrases plus `/prompt-creator`) and two negative triggers. Superpowers goes further and bans the *additional* workflow clause. Treating G1 as a defect therefore means adopting a stricter rule than this repo has written down — see P1 and Q6.
- **G2 — the rubric is summarized twice.** `SKILL.md:25` hardcodes a "stable core" list in the always-loaded body, duplicating the reference file and refreshed by neither the live fetch nor a checklist edit.
- **G3 — verification modelled as one tier.** *Give Claude a way to verify its work* now gives four gating tiers — in-prompt, a `/goal` condition re-evaluated every turn, a `Stop` hook blocking the turn from ending, and a verifier subagent — and states the `/goal` and Stop-hook tiers are what let an unattended run finish correctly. [`checklist:12`](../../plugins/prompt-creator/skills/prompt-creator/references/best-practices-checklist.md) and `SKILL.md:25` carry only the first.
- **G4 — coverage is shallow, and one section is at zero.** The live page has **10 body H2 sections** (12 `<h2>` elements less the "Documentation Index" and "On this page" chrome). *Configure your environment* — CLAUDE.md authoring, permissions, CLI tools, MCP, hooks, skills, subagents, plugins — has **zero** representation. *Automate and scale* has exactly one of its four H3s: [`checklist:20`](../../plugins/prompt-creator/skills/prompt-creator/references/best-practices-checklist.md) carries *Add an adversarial review step* (and is itself the subject of Q1), while `claude -p`, `/batch` and auto mode are absent. Elsewhere the pattern is one or two H3s out of several: absent are `/btw`, `/verify`, checkpoints, `--continue`/`--resume`, and three of the five *named* failure patterns. Nothing in the file is wrong — the failure is depth.
- **G5 — no branch for "too big for one prompt".** *Let Claude interview you* prescribes interview → `SPEC.md` → **fresh session**; [`checklist:16`](../../plugins/prompt-creator/skills/prompt-creator/references/best-practices-checklist.md) inherited only the trailing self-contained-spec sentence and dropped the workflow producing it. `SKILL.md:23` branches on exploratory intent, never on scale.
- **G6 — demands evidence of its output, states none of its own.** On a successful fetch nothing requires naming source and date; the source is disclosed only on failure (`SKILL.md:21`). Contrast `skills/verification-before-completion/SKILL.md:40-48`.
- **G7 — ambiguity handling is a count, not a protocol.** `SKILL.md:23` says "1–3 targeted questions" — no one-question-per-message rule, no rule against rewriting the clear half of a partly-unclear request (`skills/brainstorming/SKILL.md:88-92`; `skills/receiving-code-review/SKILL.md:40-57`).
- **G8 — no negative control in evals.** [`evals.json`](../../plugins/prompt-creator/skills/prompt-creator/evals/evals.json) holds four prose expectations; nothing establishes the skill *caused* the behavior rather than the model doing it anyway. Superpowers' RED phase runs the scenario **without** the skill first (`skills/writing-skills/SKILL.md:556-560`).

## Proposals, prioritized

**P1 — Strip the workflow summary from both descriptions. ADOPT.** `SKILL.md:3-12`, `plugin.json:4`: keep trigger phrases and negative triggers (both answer *when*), delete the "Fetches… and rewrites…" clause. Rule: `skills/writing-skills/SKILL.md:150-158` — **one authority, not two.** Per G1 this tightens beyond [CONVENTIONS.md:20](../CONVENTIONS.md) rather than enforcing it, so it rests entirely on Superpowers' measured regression; the repo-wide version of the rule would need a CONVENTIONS.md amendment, which is out of scope here (Q6). Cost: minutes, but re-run `evals.json` — the whole premise is that description wording changes behavior. Best value/cost ratio here.

**P2 — Delete the hardcoded rubric summary from the body. ADOPT.** `SKILL.md:25`: replace the inline list with a pointer to the reference, leaving one copy that a checklist edit updates. Rule: CONVENTIONS.md "Don't inline what a sibling file can hold on demand"; `skills/writing-skills/SKILL.md:72-91`. Knowing tradeoff: today the body supplies rules without a file read; afterwards the live page does — the intended source anyway.

**P3 — Rebuild the fallback checklist against the live page's shape. ADOPT.** `references/best-practices-checklist.md`: restructure around the live H2s instead of a flat 10-item list; add the four-tier ladder (G3), the plan-mode skip heuristic ("if you could describe the diff in one sentence, skip the plan"), the five named failure patterns, `/btw`, `/batch`, `claude -p`, the bundled `/code-review` skill; re-date. Rules: *Give Claude a way to verify its work*, *Automate and scale*, *Avoid common failure patterns*. Cost: largest item — the file roughly doubles. See Q2 — resolved: one file.

**P4 — Classify and announce the request shape. ADAPT.** `SKILL.md`, new step before diagnosis: sort the rough prompt into a fixed small set (one-shot task, bug, large feature, exploratory, unattended run) and state the classification out loud so the user can override it. Adapted from `skills/brainstorming/SKILL.md:22-34` — **adapted, not adopted**, since their three paths are lifecycle paths and ours are prompt shapes. This is what makes P3 usable: it selects which subset of a much larger rubric applies rather than applying all of it every time, and it is the natural home for G5's routing. Cost: medium.

**P5 — State the guidance source and date in the output. ADOPT.** `SKILL.md:27-30`: one line in the deliverable — live URL + fetch date, or fallback + staleness warning. Rule: the `Not Sufficient` pattern (`skills/verification-before-completion/SKILL.md:40-48`) and CONVENTIONS.md "Show the validate output as evidence — don't assert". Cost: trivial; makes the skill's core promise checkable rather than assumed.

**P6 — Tighten the ambiguity protocol. ADAPT.** `SKILL.md:23`: replace the bare count with one question per message, prefer multiple choice, and if *any* item is unclear do not rewrite the parts that are clear (`skills/brainstorming/SKILL.md:88-92`; `skills/receiving-code-review/SKILL.md:40-57`). Keep the "vague is sometimes right" exception — *Develop your intuition* licenses it explicitly. Cost: small.

**P7 — Add a negative-control eval. ADAPT.** `evals/evals.json`: add a case running a representative rough prompt with the skill *absent*, so a reviewer can tell whether the skill changed anything (`skills/writing-skills/SKILL.md:556-560`). Cost: small as data; not runnable by the compliance script (Q4).

### Rejected

**R1 — A `SessionStart` hook injecting this skill's trigger rules. REJECT.** Superpowers' highest-leverage mechanism (`hooks/hooks.json:1-17`), wrong here twice: out of scope by this PRD's terms, and substantively wrong for a narrow user-initiated skill. They pay that per-session cost for a methodology governing *every* task; `prompt-creator` fires when someone says "improve this prompt". Injecting it into every session is exactly the context burn the live page's core constraint warns against.

**R2 — A red-flag / rationalization table. REJECT.** The most imitable Superpowers device, and their own evidence says it backfires here. `skills/writing-skills/SKILL.md:463-470` scopes those tables to *discipline* failures and prescribes a **positive recipe** for wrong-shaped output, reporting the prohibition arm produced clearly more unwanted content than the recipe arm and trended worse than no guidance at all; `:480` restates the limit. `prompt-creator`'s failure mode is output shape (a mediocre rewrite, or executing the task instead of rewriting it), not a rule skipped under pressure. P4 is the recipe-shaped alternative.

**R3 — Splitting into diagnose/rewrite skills. REJECT.** Superpowers splits on *triggering moment*, not topic — `requesting-` vs `receiving-code-review` are separate because they fire at different instants. Diagnosis and rewriting fire at the same instant on the same turn. One skill.

**R4 — Importing the `<500 word` budget and the graphviz vocabulary. REJECT.** `SKILL.md` is 426 words (`wc -w`), already inside Superpowers' own budget (`skills/writing-skills/SKILL.md:213-221`) and far inside this repo's 20KB warning; a second numeric budget constrains nothing. Note for implementation, though: that leaves ~74 words of headroom, so P4 and P5 should be written tight if the budget is treated as a soft target. Their diagram conventions are graphviz `dot` in fenced blocks, conflicting with [CONVENTIONS.md:108](../CONVENTIONS.md) (Mermaid only) and not rendering in Claude Code regardless.

## Conflicts with this repo's conventions — named, not adopted

- **Authority.** Superpowers' `CLAUDE.md:40-42` refuses PRs that reword skills to conform to Anthropic's published skill guidance without eval evidence, treating skill bodies as tuned behavior code. [CONVENTIONS.md:13](../CONVENTIONS.md) makes that same page *the* authority this repo tracks. Direct conflict; this PRD sides with the repo and cites Superpowers for **mechanisms**, never as a competing rubric. On `description` both agree it must say *when* — the dispute is whether it may *also* summarize the workflow, where a reproduced regression favors Superpowers.
- **Size.** Their meta-skill is 26KB of `SKILL.md` against a self-declared <500-word target and this repo's 20KB budget. Import the mechanism, not the body size.
- **Reference depth.** Their bundled Anthropic reference forbids nested references (`skills/writing-skills/anthropic-best-practices.md:353-357`) and their own tree breaks it. P3 must keep the checklist one level from `SKILL.md`, per [CONVENTIONS.md:55](../CONVENTIONS.md).
- **Already aligned, no action:** `SKILL.md:21` links its reference with a markdown relative link, not `@` — what `skills/writing-skills/SKILL.md:278-288` requires, since `@` force-loads the file immediately.

## Resolved questions

Recommended answers with the evidence each rests on. All are overridable by the owner; the implementation session should treat them as settled unless told otherwise.

**Q1 — Reviewer scoping. → (b) ask-for-all-then-filter, recorded as a deliberate deviation.**
The conflict is real: the live page still tells the reviewer to flag only gaps affecting correctness or stated requirements, [`checklist:20`](../../plugins/prompt-creator/skills/prompt-creator/references/best-practices-checklist.md) faithfully reproduces it, and [MODEL-NOTES.md:37](../MODEL-NOTES.md) names that exact phrasing an Opus 5 hazard. Three things break the tie toward (b). First, Superpowers reached the same design independently: its live reviewer template asks for **all** issues bucketed Critical/Important/Minor (`skills/requesting-code-review/code-reviewer.md:143`), its calibration block says categorize, never suppress (`:78-87`), and the two templates that *do* impose a severity floor are orphaned — nothing under `skills/brainstorming/` or `skills/writing-plans/` references them. Second, (b) serves the live page's *intent* (stop review findings driving over-engineering) by moving the filter from the reviewer to the requester, rather than contradicting it — the page's goal survives, only the mechanism changes. Third, this repo already has the precedent and the pattern for exactly this: [MODEL-NOTES.md](../MODEL-NOTES.md) § *Deliberate deviations* records a knowing departure from model guidance with its rationale.
Implementation: `checklist:20` keeps the live rule and gains one adjacent line naming the deviation and citing MODEL-NOTES. Not (c) — a caveat leaves the hazardous wording in the emitted prompt, which is the thing that actually reaches a reviewer.

**Q2 — Reference split. → One file. (Corrects this PRD's own framing.)**
The "nested-reference trap" argument was wrong: two references both linked directly from `SKILL.md` are siblings, not nested, and `skills/writing-skills/anthropic-best-practices.md:353-357` bans only the SKILL.md → A → B chain. The real arguments still favour one file. The checklist is **fallback-only**, read solely when the live fetch fails, so its load cost is already conditional — splitting it optimises the rarest path while adding a routing decision to it. Superpowers' own extraction threshold is 100+ lines (`skills/writing-skills/SKILL.md:72-91`); a checklist that doubles to ~50 lines does not meet it. Mitigate the skimmability risk with structure inside the one file — the live H2s as headings — not with a second file.

**Q3 — Large-feature routing. → Stay in lane; emit the interview-kickoff prompt.**
There is no real conflict to resolve. The live page's *Let Claude interview you* flow **begins with a prompt** — the page ships a copy-paste one — so for a large feature `prompt-creator`'s correct deliverable is that kickoff prompt, adapted to the user's feature, plus the page's instruction to execute the resulting `SPEC.md` in a fresh session. That is simultaneously staying in lane and following the rubric. A hand-off would have the skill decline its own job to recommend a workflow it could have produced the entry point for.

**Q4 — Plugin-local trigger test. → No. Out of scope, and the faithful pattern is repo-level anyway.**
Decisive on Superpowers' own layout: **no runnable test scripts live inside `skills/`**. The `.sh` files there are tools (`find-polluter.sh`, `brainstorming/scripts/start-server.sh`) and the `test-*.md` files under `systematic-debugging/` are prose scenarios; every runnable test sits at repo root under `tests/`. Copying the pattern faithfully therefore lands outside this plugin, which is marketplace-wide work this PRD excludes. It also needs API credentials and a runner that neither `claude plugin validate` nor `scripts/check_compliance.py` provides. Right home: [ROADMAP.md](../ROADMAP.md) Phase 2, alongside the existing non-interactive-Claude-in-CI item. P7 stays in scope because it is data only.

**Q5 — Version. → Yes, `0.2.0`, in five places.**
Precedent is behavioral-change-gets-a-minor-bump: `linear-flow` went `0.1.0`→`0.2.0` for the PR relation gate, adding no skill. P1–P7 change the description, the procedure, and the reference, so the bump is warranted. Per [PITFALLS.md](../PITFALLS.md) (2026-07-31), the five locations are `plugin.json`, the `marketplace.json` entry, [FEATURES.md](../FEATURES.md) line 3 (the "nine are at `0.1.0`" count sentence), [STACK.md](../STACK.md) line 32 (the same count), and [ROADMAP.md](../ROADMAP.md) line 32 ("shipped at `0.1.0`"). Note that two of those are *count* sentences, not per-plugin mentions — grepping for `prompt-creator` alone misses them, which is how this pitfall recurs.

**Q6 — Repo-wide description rule. → Plugin-local now; fold the general question into the existing ROADMAP item, gated on evidence.**
Do not amend [CONVENTIONS.md:20](../CONVENTIONS.md) as part of this work. [ROADMAP.md:42](../ROADMAP.md) already carries an open follow-up to review all 10 other plugins' skills against Opus 5 guidance, naming trigger-language calibration as the likely hot spot — the no-workflow-summary rule belongs there, not in a new workstream. Sequencing also matters: P1's eval re-run produces exactly the before/after evidence a repo-wide rule should rest on, and adopting a third-party rule catalogue-wide *without* that evidence is the move Superpowers itself refuses (`CLAUDE.md:93-100`). Run P1, measure, then decide.
