# Project description

> Default shape for a project description. A workspace file's own shape overrides this one. Write only what the user actually gave — an empty section beats an invented requirement, and a section with nothing real in it should be dropped, not padded.

## Objective

What this project is for, in one or two sentences. The outcome, not the activity.

## Scope

What is included. Where useful, an explicit *not* included — the boundary is usually the valuable half.

## Constraints and context

Deadlines, dependencies, technical or client constraints, prior decisions that bound the work.

## Expected delivery

What "delivered" looks like concretely, and roughly when if a date is known.
